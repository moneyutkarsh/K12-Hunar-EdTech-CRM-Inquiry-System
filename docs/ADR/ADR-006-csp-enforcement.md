# ADR-006: Progressive Content Security Policy (CSP) Enforcement

## Status
Accepted (Report-Only Phase Active)

## Context
K12 Hunar CRM incorporates rich interactive WebGL canvas elements (AeroShards, GridScan, GhostFibers), Google Fonts, Vite bundle splitting, and dynamic SVG icons. Abruptly enforcing a strict Content Security Policy (`Content-Security-Policy: default-src 'self'`) in production risks breaking WebGL shader compilation, inline CSS styles generated by animation frameworks, or external API communication to Render and Supabase.

## Decision
1. **Phase 1: Report-Only Monitoring (Current)**:
   Deploy `Content-Security-Policy-Report-Only` via edge headers in `frontend/vercel.json`. This surfaces all potential policy infractions in developer consoles and monitoring telemetry without intercepting or interrupting user experiences.
2. **Key Allowed Origins**:
   - `script-src 'self' 'unsafe-inline' 'unsafe-eval'`: Allows dynamic shader and bundle execution.
   - `style-src 'self' 'unsafe-inline' https://fonts.googleapis.com`: Accommodates Tailwind CSS and Google Fonts.
   - `font-src 'self' data: https://fonts.gstatic.com`: Allows web font assets.
   - `connect-src 'self' http://localhost:* https://*.onrender.com https://*.supabase.co wss://*.supabase.co`: Authorizes API and database communication.
   - `frame-ancestors 'none'`: Mitigates clickjacking attacks.
3. **Phase 2: Promotion to Enforcement**:
   - Following a 14-day production monitoring window with zero false-positive CSP violations, migrate header name from `Content-Security-Policy-Report-Only` to `Content-Security-Policy`.
   - Remove `'unsafe-inline'` where feasible by computing SHA-256 script hashes during CI build steps.

## Consequences
- **Positive**: Zero risk of breaking production rendering or UI animations; complete visibility into asset origin compliance.
- **Negative**: Malicious script injection is logged rather than blocked until Phase 2 promotion.
